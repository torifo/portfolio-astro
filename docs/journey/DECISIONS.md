# Journey の決定事項 — 誰が決めたか

Journey（Instagram の投稿を都道府県・旅・聖地巡礼・テーマで辿るページ）の判定規則と運用の決まりを、
決定主体ごとに分けて記録する。変更したくなったときに、誰に確認すればよいか、何を測り直せばよいかが分かるようにするためである。

| 区分 | 意味 | 変えるとき |
|---|---|---|
| **人が新しく決めたこと** | 本人が定めた方針・運用の決まり | 本人に確認する |
| **人の判断が必要で決まったこと** | 撮影地・訪問・作品名のように、機械では決められず本人が判断した個別の事実 | 本人に確認する（`overrides.json` などに残っている） |
| **LLM が自動で決めたこと** | 実装の細部・閾値・名称・順序。この作業を進めた LLM（Claude Code）が、測定結果や既存の記述に合わせて決定し、結果を本人に報告したもの。本人が明示的に承認していないものも含む | 再測定してよい（`eval_resolve.py`・試験台など） |

- 対象: 2026-09-11（設計）〜 2026-10-05。設計書とその改訂、同期 PR、コミット履歴から抽出した
- 設計時（9/11）の初期決定（取り込みの土台・県ページの範囲・LLM を判定器にしない など）は、
  [設計書 §12 決定事項の一覧](../superpowers/specs/2026-09-11-journey-instagram-design.md) に記載されている
- 日付は決定した日。「置き場」は、その決まりが定義されているファイル・関数を表す

## 3. LLM が自動で決めたこと

測定結果や既存の書き方に合わせて、LLM（Claude Code）が決めた内容。本人には結果を報告している。
数字や順序は、測り直して変更してよい。

### 県の判定（`resolve.py`・`gazetteer.py`）

| 決めたこと | 根拠 |
|---|---|
| 本文の県名は地名タグより後に適用し、本文中のタグ部分は読み込まない | 正解のある 1,012 件で検証したところ、誤りが 116 → 85 件に減少した（`eval_resolve.py`） |
| 「東京湾」は県名として扱わない | 東京湾クルーズが東京に分類された原因のため。全件で判定が変わったのは猿島の1件のみ |
| 数字のみの地名（津駅の別名「12」）と、一般語・地方名（日本庭園・東北・東海・日の出・谷・森 など13語）を索引から除外する | 誤りの原因となった語を抽出し、正解を減らさないもののみを選定した |
| 小さな集落を索引から除外する案は採用しない | 誤りと同時に正解も減少したため |
| 過去の投稿のタイトル（日付と同じ行の文）は場所として読み込まない。日付の後ろの場所は 2026-09-30 以降の投稿にのみ適用する | タイトルを場所として読み込むと、誤りが 116 → 117〜138 件に増加したため |
| 日付の後ろの場所は、区切り文字で分割した語を左から完全一致で照合し、なければ部分一致で照合する。タグで固定した施設名も適用する | 「横浜➝東京」は先頭の横浜とするため |
| 日付の後ろに県名と「趣味」が両方ある場合は、掲載しない方針を採る | 「趣味」の記述は掲載したくないという意思表示であるため |
| 県境の場所で GPS のない投稿は、同一地点の投稿のうち GPS で多い方の県に寄せる | 2件以上ある場合に GPS に合わせるという本人のルールを、GPS のない投稿にも適用するため |
| 十和田八幡平国立公園の県境の1件を GPS に基づき秋田に固定した | 判定規則の変更時に、公園名によって3県に広がるのを防ぎ、本番の県を変更しないようにするため |

### 撮影日（`apply_date_overrides.py`）

| 決めたこと | 根拠 |
|---|---|
| EXIF の撮影日時（エクスポートの `date_time_original`）を撮影日の根拠にする | 投稿日を使っていた100件のうち照合できた20件で、投稿日と一致したのは7件だけだったため |
| 本文の途中の「元旦」「大晦日」は1月1日・12月31日とし、「2022年冬」のように年だけのものは年までとする | 本文の先頭の日付しか読んでおらず、取りこぼしていたため |
| 年までの日付は1月1日に寄せ、日付不明は投稿日を並び順のためだけに残す | 日付の文字列で並べる・数える箇所を壊さないため |
| 県・テーマのページの年の範囲は、日付不明を除いて数える。旅の判定・旅の日数・聖地巡礼の期間・同期 PR の「同じ日」「旅の期間外」は、年までと日付不明の両方を除く | 1月1日の投稿や投稿日と混ざって、旅の判定が狂うのを防ぐため |
| 年まで・日付不明は `date_overrides.json` の値（`"2022"`・`"unknown"`）で書く | 撮影日の指定の置き場を一つにするため |

### テーマ（`build_themes.py`）

| 決めたこと | 根拠 |
|---|---|
| テーマに投稿IDで入れる `extraPostIds` を設ける | テーマはタグでしか決まらず、タグのない投稿（桜道のリール・フラワーコレクション）を入れられなかったため |

### 同期 PR の点検（`sync_report.py`）

| 決めたこと | 根拠 |
|---|---|
| 「旅の主な県と不一致」は main の旅と比較する | 新着込みで組み直した旅と比較すると、新着自身で一致して PR #3 の4件を見逃したため |
| 「同じ日の投稿と県が違う」は、対象が2件以上かつ6割以上が同じ県であるときとする | 過去の投稿に適用したところ、要確認 62 件のうち 44 件が実際の誤りだったため |
| 人が県を決めた投稿（overrides・日付の後ろの場所・趣味）は、県の食い違いを点検しない | 本人の指定を機械の推測で疑わないため |
| 日付の後ろに場所が書かれていても、要確認が出た投稿は保留にする | 誤入力を検知できるように残すため（訪問済みの県の「初めての県」は、その後本人が外した） |
| 新着が含まれる聖地巡礼の作品は本文に出すが、要確認にはしない | 作品名がなくても自動マージを止めないため |

### 自動マージと PR の分け方（`open_sync_prs.sh`）

| 決めたこと | 根拠 |
|---|---|
| マージは `GHCR_TOKEN` で行う | `GITHUB_TOKEN` でマージした push では Deploy が起動しない（GitHub の仕様） |
| マージの前に、GitHub がマージ可能かを判定するまで最大30秒待ち、失敗した場合は15秒後に1回だけ再試行する | 作成直後の PR はマージ可能かが未判定のことがある（Fable のレビューでの指摘） |
| 分割時は自動マージ側を先にマージし、その main から取り込み直して残りの PR を作る。残りのブランチは `journey/sync-日付-hold` とする | 2つ同時に作ると posts.json などで衝突する |
| 取り込み直しで保留の投稿を取得できなければ、警告を出して終了する | API は既知の投稿のみのページで読み込みを終了するため、新着が多い日は拾い損ねる可能性がある |
| bash では変数の直後に全角文字を置かない（`${var}` と書く） | 日本語ロケールの bash は全角文字の一部を変数名として解釈し、未定義変数で停止した |

### 定時実行（`journey-sync.yml`）

| 決めたこと | 根拠 |
|---|---|
| 8:00 → 7:17 → 2:47 JST。0分・30分を避ける | 毎時0分は混雑して取りこぼされる。同じアカウントの別のリポジトリも毎回2〜3時間遅れていた |

### 聖地巡礼（`build_pilgrimages.py`）

| 決めたこと | 根拠 |
|---|---|
| 作品は `pilgrimages.json` の works を辞書として判定する。初期の作品名・別名・slug（`ラブライブ！サンシャイン!!`・`sukimega` など）はタグから作成した | 件数で判定すると1件だけの作品が漏れ、旅の名前が作品になってしまうため |
| 旅の名前のタグは、登録済みの旅、または「…旅」「…編」などで終わる8文字以上のタグとし、それだけでは聖地巡礼に数えない | 旅の判定（`build_trips.py`）と判定基準をそろえたため |
| 作品名のないまとめは「作品名なし」（slug `untitled`）とし、作品数には含めない。ページの見出しは「作品名のない聖地巡礼」とする | — |
| 投稿がまだない作品も辞書に残すが、サイト上には0件の作品を表示しない | 辞書を消さずに育てるため |
| 聖地の場所は、タグを人が登録する（`spots`）。聖地巡礼の投稿と同じタグを持つ投稿を自動で足す方法はとらない | 同じ旅で共有するタグで広げると、`#青春18切符`・`#晴天`・`#銚子電鉄` などで無関係な投稿が入り、浜松編のさわやか（10/04 に外した）も戻った。伊勢志摩スカイラインは地名の辞書にもない |
| 個別に入れる投稿は `extraPostIds` に書く（テーマと同じ名前）。該当する投稿がない ID は `build_pilgrimages.py` が知らせる | 本文に作品名が書かれていてタグが付いていない投稿を、タグを付け直さずに入れるため |
| ざつ旅を辞書に先に足す（slug `zatsutabi`、別名「ざつ旅」） | タグを付けたら、その投稿がそのまま作品に入るようにするため（取り込み済みの投稿は `journey:refresh` で読み直したあと） |

| 全ページを読み、キャプションが変わった投稿の本文とタグだけを書き換える。新着は足さない（同期の PR で取り込む） | 同期の PR と自動マージの流れを変えないため |
| 撮影日は本文から読み直すが、人が指定した撮影日（`date_source` が manual）はそのままにする。県の指定・サムネ・個別リンクには触れない。API が本文を空で返した投稿は上書きせずに飛ばす | 人の指定を上書きしないため。API の欠けで本文とタグを消さないため |
| 旅のタグを付け直したら、`trips.json` の tag・title を新しいタグに書き換えてから組み直し、旅の URL を引き継ぐ | 旅は旅のタグで同じ旅と見分けるので、そのままだと slug が変わって今の URL が消える |
| 定時の同期には組み込まない（手で流す） | 取り込み済みの投稿の変更を PR でどう見せるかを決めていないため |
