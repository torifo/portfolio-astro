# Journey 県判定の精度改善 — 設計

- 日付: 2026-09-30
- 対象: `scripts/journey/resolve.py`・`gazetteer.py`・`sync_report.py`・新規 `eval_resolve.py`
- 親の設計書: [2026-09-11-journey-instagram-design.md](2026-09-11-journey-instagram-design.md)

## 背景

同期PR #3 で、東海汽船 東京湾クルーズの新着4件が全件東京都になった（正しくは2件が神奈川県）。

- Instagram API は投稿の位置情報を返さない（`fields=location` は存在しないフィールド）。
  Actions の同期では、新着の県は本文とタグの文字だけで決まる
- PR の点検「旅の主な県と不一致」が、新着込みで組み直した旅と比べていたため素通りした
  （PR #3 で修正済み。main の旅と比べる）
- Instagram のハッシュタグは5個までなので、場所のために1枠使う運用は難しい

## 1. 精度を測る（eval_resolve.py）

- 正解: 人の指定（`method: override`）があればその県、なければ GPS の県（resolved.json の
  `gpsPrefCode`）。gps.json を読まないので、手元でも Actions でも動く
- 予測: 新着と同じ条件で全件を判定し直す。GPS と投稿IDの指定は使わず、タグの指定
  （`#東京ディズニーシー` → 千葉など。新着にも効く）は使う
- 出力: 正解・誤り・決まらないの件数と、根拠別の正解率。`--save` で結果を保存し、
  `--compare` で前回から直った・壊れた投稿を出す
- 判定ルールを変えるときは、必ずこれで前後を比べる

## 2. 判定の層と除外語（測って決めた）

| | 正解 | 誤り | 決まらない |
|---|---|---|---|
| 変更前 | 730（72.3%） | 116（11.5%） | 164 |
| 変更後 | 746（73.7%） | 85（8.4%） | 181 |

正解のある 1,012 件（人の指定か GPS で県が確かめられた投稿）に当てた数字。
誤りが決まらないに移った分は、PR の要確認（県が不明）に出るので人が気づける。

採ったもの:

- **本文の県名を地名タグより後へ**（L4c）。タグの県名 → 辞書 → 地名タグ → 本文の県名 → 旅タグ内の地名の順
- **本文の県名はタグの部分を読まない**。誤りの多くが、長い旅タグの一部（「…東京タワー…旅」の東京、
  「成田鹿児島与論島…」の鹿児島）を本文として拾ったものだった。タグは前の層で完全一致を調べてある
- **数字だけの地名を索引に入れない**。津駅の別名「12」が「12月」に当たり9件を誤らせていた
- **除外語を足す**: 日本庭園・東北・上方・離島・空港前・海岸・日の出・ひまわり・大橋・谷・森・鳥居・東海。
  一般語・地方名・小さな集落の名前が本文で当たっていた（東海は `#東海汽船` の中で愛知県の東海市に当たる）

採らなかったもの:

- 裏付けの少ない集落（サイトリンク3未満）を索引から外す案: 誤りと一緒に正解も減った
- 旅タグに埋まった県名を別の層で拾う案: 上の変更と合わせても差が出なかった

本番の県は1件も変えていない。変更で県が変わる3件は人の指定で今の県に固定した
（十和田八幡平の県境は GPS の秋田、初日の出・星空は本人の判断で今のまま）。

## 3. 日付の後ろの場所（L1b）

投稿するとき、日付と同じ行に場所を書くと最優先で使う（人の指定 L0 の次）。

```
2025-06-28 横浜
東海汽船 東京湾クルーズ
```

- 2026-09-30 以降に投稿したものだけに効かせる。それより前の投稿の同じ行は題
  （`2023年9月6日 父母ヶ浜 Part3`）で、題を場所として読むと誤りが 116 → 117〜138 件に増えた
  （「町田~USJ」「高松駅（さらば四国）」のように撮影地以外の地名がよく入っている）
- 区切り（空白・・・/・➝・→・〜・括弧など）で分けた語を左から完全一致で当て、無ければ部分一致を
  左から当てる。「横浜➝東京」なら横浜。タグで固定した施設名（東京ディズニーシー → 千葉）も効く
- 読めなかったときは PR の要確認に「日付の後ろの場所を読めない」と出る。書き方は運用しながら調整する
- ひらがなは読みの同じ別の地名に当たることがある（「よこはま」は青森の横浜町）。漢字で書く
- 2026-10-02〜: 新着がすべて日付の後ろの場所で決まり、要確認が0件の同期PRは自動でマージして本番に出す

## 4. 同期PRの点検「同じ日の投稿と県が違う」

- 対象: 新着のうち人が県を決めていない投稿（overrides と日付の後ろの場所は見ない。2026-10-02 に日付の後ろの場所も外した。同期PR #5 で、場所を「東京」と書いた投稿が八景島の日だったため要確認に出ていた）
- 相手: 撮影日が同じほかの投稿（main の既存と同じPRの新着）。県は最終判定を使う
- 条件: 相手が2件以上あり、6割以上が同じ県で、その県が新着の県に含まれない
- 表示: 「同じ日の22件中19件は神奈川県」
- 旅に入っていない単発の投稿の誤りを拾うため。既存の投稿に当てると要確認 62 件のうち 44 件が
  本当の誤り（文字だけの判定の誤り 85 件中 44 件を捕捉）。PR #3 の状態に当てると4件とも出る
